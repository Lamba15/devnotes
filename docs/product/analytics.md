# Website Analytics

Devnotes owns the first-party analytics system for `nouraboelsoud.com`.
The public website sends anonymous usage events to the Devnotes API, and the
resulting dashboard is available only to the platform owner under CMS.

## Measurement goals

The dashboard should answer four questions:

1. How many people and sessions reach the website?
2. Which portfolio, education, lecture, and project pages attract attention?
3. Do visitors meaningfully engage, continue to another page, play a lecture,
   open the presentation, or contact Nour?
4. Where do visitors arrive from and which devices do they use?

## Core definitions

- **Visitor**: an anonymous browser identifier generated by the public site and
  stored in local storage. The API stores only an HMAC hash of the identifier.
- **Session**: activity from one anonymous visitor grouped by a rolling
  30-minute inactivity window.
- **Page view**: one client-side route view. SPA navigation counts as a new page
  view without requiring a full reload.
- **Active engagement time**: seconds while the page is visible and the visitor
  has interacted within the previous minute. Background-tab time is excluded.
- **Bounce**: a session with exactly one page view, fewer than 10 active seconds,
  and no meaningful action.
- **Engaged session**: a session with at least 10 active seconds, at least two
  page views, or a meaningful action.
- **Meaningful actions**: video start/completion, presentation open, WhatsApp
  contact, or an outbound project visit.

Rates use sessions as their denominator. Average engagement time is the sum of
active seconds divided by sessions. Scroll depth is the maximum percentage of a
page reached by a visitor.

## Content taxonomy

- `/` is `home`.
- `/projects` is `projects_index`.
- `/projects/{id}` is `project`, with the project ID attached.
- `/education` is `education`.
- `/education/presentations/{slug}` is `lecture`, with the presentation slug
  attached.
- Any other rendered public route is `other`.

The dashboard provides all-site, portfolio, projects, education, and lecture
filters. A filtered session is a session that included at least one matching
page view. Page views, engagement time, bounce/engagement classification, and
meaningful actions in a filtered view are calculated only from matching pages
and events.

## Privacy and data boundaries

- Do not store raw IP addresses.
- Do not store names, email addresses, WhatsApp numbers, form values, URL query
  strings, URL fragments, or full outbound URLs.
- Store only the path, referrer host, optional same-site referrer path, campaign
  tags, device class, browser family, language, and coarse country header when
  one is supplied by trusted infrastructure.
- Hash visitor and session identifiers with the application key before storage.
- Reject unsupported event names and bound event payload sizes.
- Rate-limit the public ingestion endpoint.
- Retain raw analytics records for 13 months, then prune them.

## Dashboard layout

The default 30-day view is summary-first:

1. visitors, sessions, page views, bounce rate, engagement rate, and average
   active time;
2. daily traffic and engagement trend;
3. education funnel and meaningful-action counts;
4. top pages and project views with depth metrics;
5. traffic sources, devices, and event breakdowns;
6. metric definitions and source freshness.
